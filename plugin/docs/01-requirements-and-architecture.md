# 01 · 需求与架构

更新日期：2026-10-20，依据当前 `0.4.2` 源码。精确合同见 [00](<00-current-contract.md>)，证据状态见 [05](<05-current-status.md>)。
本文解释设计理由，不用早期 Core 取证或历史绿数代替当前宿主验收；[旧架构稿](https://github.com/KouzakiUmi/dsh-tool-discovery/blob/b12dfef1815636c1518f741da870c1dd5427442f/plugin/docs/01-requirements-and-architecture.md)可用于追溯设计演进。

## 1. 真正要解决的问题

成本来自**过早披露**：任务只用少数工具，却先携带大量名称、用途和参数。把全量 schema 改写成 Markdown 或技能全文，并不改变整份输入仍在上下文里的事实。

设计将六种能力分开：类别导航、名称浏览、类别内任务检索、显式版本选择、可选可信使用指导、原生执行。
目录是宿主 registry 与 scope 的投影，不是独立授权数据库；不引入外部搜索服务、embedding 或第二套执行器。
工具规模、token 数与延迟收益需要对应测量，不把最初的用户观测当作当前实测基线。

## 2. 目标、非目标与边界

### 2.1 当前目标

- 首轮给三个发现入口、简短类别导航及**本周期初始集合**，其余工具按需披露。
- 浏览只列完整名称，搜索只给任务候选；二者不改变选择。
- 加载明确选择当前合格版本，不执行目标工具、不批准副作用；下一轮才披露。
- 在健康 native 周期内保留实际披露 wire 与首见顺序，旧 wire 与当前执行资格分别管理。
- 宿主仍负责原名称解析、参数、审批、沙箱、输出、超时、取消、调度和 UI。

### 2.2 不做什么

不自动安装工具、不默认整类加载、不使用通用执行转发器、不静默 LRU 卸载、不承诺未测试 Core 兼容或无停顿热替换原子绑定。
同会话多活动 agent 并发不声明支持。PTC 默认旁路，可选适配已有实现，但 SDK 逐字冻结、稳定追加与跨重启冻结尚未闭合。

### 2.3 初始集合是独立策略

默认手动名单取手工维护的核心工具表，且独立保留当前实际 preset 的自有可见工具。三个入口不由名单开关删除。
默认核心同名自证还有一条 guard 例外；想让手动/preset 名单成为精确边界，需理解 `respectAlwaysVisible`。
可信 `frameworkRetained` 是组合方保留项，不按名字含 output/result 自动判断。
因此不能把“其它普通工具按需”写成“任何未经 load 的工具都不可执行”。

## 3. 交互形态

```text
首轮：三入口 + 类别导航 + 初始工具
名称浏览 / 任务搜索 / 已知精确名
                 ↓
     tool_load：资格、版本、冻结冲突、预算
                 ↓
        canonical 最终成功结果核验
                 ↓
     下一轮实际披露 → 调用宿主原工具
```

不强制 `list → search → load` 三轮。已知名字可直接加载；搜索返回的 ref 额外绑定签发版本。
“确认加载”是模型显式选择，不是用户点击审批。内核支持版本化技能，但当前生产 registry 的 `skill` 为 null，不承诺外部技能服务已接入。

## 4. 六类数据必须分开

| 数据 | 用途 | 不包含 |
|---|---|---|
| CategoryCard | 可信导航与统计 | 目标工具完整清单/参数 |
| NamePage | 完整名称分页 | 描述、schema、ref |
| CandidateCard | 任务用途、匹配依据、短期 ref/revision | 参数 schema 或执行许可 |
| ToolSkill | 有可信元数据时的使用指导 | schema 副本、自由文件路径 |
| NativeToolSchema | 实际模型披露 | execute、UI 回调和服务对象 |
| ExecutionDefinition | 宿主内部派发 | 不作为目录内容返回 |

名称与 schema 不靠截断 required/enum 来省字节；不足时减完整项或明确失败。

## 5. 分层架构

| 层 | 职责与边界 |
|---|---|
| registry adapter | 当前 scope 可见绑定和代次；拿不到 provider 来源时不猜 |
| catalog / categories | 不可变身份快照与受控分类；类别不是授权 |
| list / search | 只读发现；检索须有工具级证据，不用类别词凑候选 |
| protocol / budgets | 严格字段校验；可选限额默认关闭，输出策略仍分页 |
| engine / reducer | pending、完整回执核验、最终结果提交次序、选择与冻结恢复 |
| journal | canonical 配对、own-only 历史与实际 header 观测；不从 header 生成选择 |
| native projection | 保留有资格基线、有效选择与冻结内容；首见顺序优先、新项追加 |
| guard | 只增加拒绝；初始/框架/核心例外与普通按需路径分别判断 |
| PTC | 显式开启时投影 SDK、核对实际出站文本；不复用 native 冻结承诺 |
| lifecycle / epoch policy | runtime、恢复屏障、可选 durable 名单、成功压缩与卸载清理 |
| config / client | 配置与全局登记辅助目录；不是会话执行资格面 |

[domain](<../domain/>) 不导入宿主包或做文件 I/O；[adapter](<../adapters/dsh/>)承担宿主接线。
具体调用链见 [09](<09-business-logic-map.md>)，不在架构文档复制每个实现函数或固定文件数量。

## 6. 生命周期与异常场景

### 6.1 恢复、fork 与子代理

恢复先订阅、再读 query raw 历史，并核验继承边界；fork 自己的 load 可恢复，父的继承前缀不当成子选择。
恢复未落定时等待，不以超时发送缩水工具集；恢复已失败则 fail closed，不能改称新会话。
默认子代理没有 durable 基线要求；严格子策略只认运行时真实所有权，未知身份或顶层恢复不获豁免。

### 6.2 定义变化与披露稳定性

撤权/移除使有效选择和披露凭据失效，但不要求从健康 native 周期中删掉已发送旧 wire。
同名不同 schema 须等成功压缩；同 schema 重绑或技能换版可重新选择，不能用冻结计费去重吞掉新指南。
无关 registry 变化不应无条件作废全部 ref/游标；真实身份变化才升级资格代次。

### 6.3 并发、取消与释放

加载可以有多个在途结果；调用 seq 用于归属，最终结果 seq 用于提交，热/冷归约保持一致。
预留、业务成功和 canonical 提交是不同阶段；取消、失败、回执不一致、会话销毁必须按已有归属收口。
插件释放取消本 activation 的等待，不擅自 abort 宿主/用户 signal，也不保证回撤已经发出的请求。
日志被接受不等于 fsync；崩溃耐久性和实际派发热替换窗口仍须单独验证。

## 7. 提示词与安全

外部描述、类别词、候选名与技能正文都是资料，不能覆盖系统规则。模型不提供 session/agent 身份、任意文件路径或代码给发现入口。
入口、框架保留、初始集合与普通加载工具有不同判据；通过本插件门禁也不代替宿主审批。
配置目录 partial/unknown 不应虚假断言未注册；全局目录也不能作为某会话的授信来源。

## 8. 性能模型与取舍

模型输入成本由“入口/导航/基线 + 已累计披露 schema + 搜索/回执历史”组成，不会永远停在初始大小。
发现和加载可能增加往返，是否改善首次有效操作或总任务延迟，需要与 prefill 节省一并测量。
宿主在投影前可能已收集并克隆全量 schema，不能把出站减少说成本地组装成本已按已加载数增长。

默认不让模型自主卸载；超限拒绝新增或等待用户/DSH 成功压缩。native 内容与顺序稳定是实现合同，**不是 provider prefix cache 命中率保证**。

## 9. 决策摘要

| 决策 | 收益 | 代价/未闭合项 |
|---|---|---|
| list/search/load 分离 | 发现不立即带入完整参数 | 可能多一次或多次模型往返 |
| 本地词法与受控词表 | 无额外网络、匹配可解释 | 需要维护同义词；纯类别查询可能零命中 |
| 原生投影 + 附加门禁 | 保持原调用链，不复制 execute | 其它 waterfall/provider 组合需验证 |
| 选择与冻结分开 | 撤权不改写已披露内容 | 同名 schema 升级需成功压缩 |
| canonical 最终结果作提交源 | 回执可重算、支持恢复 | 必须区分结果次序、归属与可验证历史 |
| 可选 durable 初始名单 | 需要时加强来源约束 | 记录缺失或存储失败可阻断旧会话 |
| PTC 默认旁路、显式兼容 | 不强制改变原生 SDK 会话 | 冻结/稳定追加/跨重启仍待实现 |
