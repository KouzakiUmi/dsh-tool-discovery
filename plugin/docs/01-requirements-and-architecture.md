# 01 · 需求与架构

更新日期：2026-11-06。依据 manifest `0.6.0`，支持 DSH Core `0.2.2-rc.1+`。精确行为以 [00 当前合同](<00-current-contract.md>) 为准，设计背景见 [14](<14-rc1-redesign.md>)，证据状态见 [05](<05-current-status.md>)。

## 1. 真正要解决的问题

任务通常只需要一部分工具，提前披露大量名称、用途和参数会增加模型输入。设计把类别导航、名称浏览、任务搜索、显式选择与宿主执行分开，不另建工具注册表或执行器。

减少披露是设计目标；是否节省 token 或总任务时延需要实际测量，不能由工具数量推断。

## 2. 目标、非目标与边界

### 2.1 当前目标

- 首轮提供 `tool_list`、`tool_search`、`tool_load`、`tool_unload` 四个入口、有界类别导航和初始工具集合；不是只提供四个入口。
- 浏览与搜索不改变选择；按名称或候选加载当前合格定义，撤销则收回准入。两者都不执行目标工具、不批准副作用。
- admission 是披露和执行的共同事实源。加载或卸载立即提交，声明从下一请求起变化；同一步的 toolSet 已定型，加载当步不可调用新工具。
- 宿主仍负责名称解析、参数校验、审批、沙箱、输出、超时、取消、调度和 UI；guard 只增拒绝，不替代原调度链。

### 2.2 非目标

不自动安装工具、不默认整类加载、不引入通用执行转发器，也不声称同会话多活动 agent 并发隔离或无停顿热替换原子绑定。开放版本范围不等于所有宿主版本均已验收。

### 2.3 初始集合

四入口始终保留；手动 `alwaysVisible` 默认使用核心工具名单，`initialToolsEnabled` 控制手动初始注入。`alwaysAllowPresetTools` 独立保留当前实际绑定 preset 的自有可见工具；默认模式还允许核心同名自证。`frameworkRetained` 是可信组合配置。具体例外与开关见 [00](<00-current-contract.md>)。

## 3. 交互形态

```text
四入口 + 类别导航 + 初始工具
        ↓ 浏览 / 搜索 / 精确名称
 tool_load → 立即提交 selected 与 admission
        ↓ 下一请求披露 → guard → 宿主原执行链
 tool_unload → 立即撤销 admission → 下一请求收回，立即拒绝执行
```

不强制先浏览或搜索；已知名称可直接加载。候选 ref 和可选 revision 受当前会话、目录资格及版本校验。协议版本为 `3`，入口拒绝未知字段及模型指定的会话身份、路径或代码。

## 4. 数据与职责

类别卡、名称页和搜索候选用于发现；候选不包含参数 schema，也不是执行许可。完整定义由宿主向模型披露并负责派发。预算不足时应减少完整项或明确失败，不通过截断必需参数改变 schema。

## 5. 分层架构

| 层 | 职责 |
|---|---|
| catalog / categories | 基于当前 scope 可见绑定建立目录与分类，不赋予权限 |
| list / search | 名称浏览和候选搜索，不提交选择 |
| protocol / budgets / state / engine | 参数校验、预算和选择事务；加载与撤销立即提交 |
| registry / restriction-view | 从忽略本插件掩码的可见面建立目录，保证被遮工具仍可发现 |
| mask / restrict | 控制可遮工具披露，先安装新限制再解除旧限制 |
| guard / admission | 执行前按准入与当前定义摘要判断，只增拒绝 |
| admission storage / lifecycle | 内存状态与 `storageDomain` 持久化、恢复对齐和运行时生命周期 |
| config / client | 配置及全局登记辅助目录，不等于会话执行资格 |

[domain](<../domain/>) 不导入宿主包或做文件 I/O；[adapter](<../adapters/dsh/>) 负责宿主接线。模块与调用链详见 [09](<09-business-logic-map.md>)。

## 6. 掩码、执行与恢复

### 6.1 披露掩码

allow-list = 四入口 ∪ `frameworkRetained` ∪ alwaysVisible（手动、preset、核心自证）∪ admitted，之后经 `restrictableNames` 过滤。宿主 `agent/created` 内同步建立 runtime 并安装初始掩码，`agent/pre-step` 兜底对齐；自身掩码造成的变更反馈按注册表指纹跳过。

当前 agent 自己 scope 注册的工具不能被掩码遮住，可能直接披露；默认启用的 `gateOwnScopeTools` 对目录内工具执行准入门禁，目录外且不可遮的名字按宿主语义放行。

### 6.2 执行判断

普通目录内工具必须 admitted，且接纳时 `schemaDigest` 与当前目录一致；未准入或定义变化时拒绝，需重新加载。入口名被同名覆盖时该名执行拒绝。初始集合与框架保留项按合同例外处理，仍受宿主权限链约束。

### 6.3 存储与生命周期

`storageDomain` 可用时 best-effort 持久化 admission；缺席或失败时退化纯内存，不阻断会话。resume 按当前目录的 `toolId` 和 `schemaDigest` 对齐持久行，不匹配或已消失的行丢弃；会话间不继承准入。撤权后立即不可执行，`in-history` 路由仍可能发送历史 schema。

## 7. 提示词与安全

外部描述和候选内容只是资料，不覆盖系统规则。全局设置目录是编辑辅助，partial 目录未列出的名字为 unknown，不是未注册证明。通过本插件门禁也不等于通过宿主审批或沙箱。

## 8. 性能模型与取舍

输入包含初始工具、后续披露的 schema 与发现交互历史；加载可能增加往返。宿主按模型路由处理历史及增量声明，撤销后历史 schema 可能仍被发送。缓存命中、token 和延迟须以真实请求测量。

## 9. 决策摘要

| 决策 | 收益 | 边界 |
|---|---|---|
| 四入口分离发现、加载与撤销 | 显式控制准入与披露 | 可能增加模型往返 |
| 掩码加执行门禁 | 不替换宿主执行链 | own-scope 不可遮，历史 schema 可能保留 |
| 准入单一事实源与持久快照 | 披露和执行一致，支持恢复 | 存储失败时仅内存有效 |
| PTC SDK 与原生定义同源 | 使用同一掩码 | 不推断真实 provider 或所有版本已验收 |
